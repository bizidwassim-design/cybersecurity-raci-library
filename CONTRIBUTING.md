# Contributing

Thanks for helping improve this library. New processes, better activity wording, corrected standard
references, sector variants and translations are all welcome.

## Ground rules

* **CSV is the source of truth.** Edit `data/<process>.csv` (and `data/processes.csv` for a new process), never
  the generated `docs/<process>.md`, `docs/index.md` or `RACI-Library.xlsx`. Regenerate and commit them together.
* **One A, at least one R, per row.** The build script enforces it. Do not argue with it in a pull request;
  split the row instead.
* **Roles are functions, not people.** No names, no real organisations, no client details. Example organisations,
  if you need any in the docs, are "Northwind Logistics", "Contoso" and "Fabrikam".
* **Standards by identifier only.** Cite `ISO 27001 A.8.8`, `ISO 42001 A.6.2.6`, `NIST CSF PR.PS-01`. Never paste
  the standards' text.
* **No macros.** The workbook stays a plain `.xlsx` generated by `scripts/build_library.py` with openpyxl.
* Be kind — see the [Code of Conduct](CODE_OF_CONDUCT.md).

## Development loop

```bash
pip install openpyxl
python scripts/build_library.py --check   # fast validation, no files written
python scripts/build_library.py           # regenerate docs/ and the workbook
git status                                # the generated files should be part of your commit
```

CI runs the same script and fails if `docs/` does not match what the CSVs produce.

## Writing a good activity row

* Start with a verb and name the deliverable: "Approve emergency changes and review them afterwards", not "Emergency changes".
* One decision or one output per row. If you need "and then", it is probably two rows.
* Give the A to the function that answers for the outcome, the R to the one that does the work; they should
  differ (see [docs/how-to-adapt.md](docs/how-to-adapt.md), section 4).
* Keep C to the functions whose input changes the result. Leave cells empty rather than filling them with I.
* Add at least one AI-related row to any new process where AI systems or training data are plausibly involved.

## Adding a process

1. Copy an existing CSV to `data/<slug>.csv` and replace the rows (keep the header byte-for-byte).
2. Add `slug,title,summary` to `data/processes.csv`; keep the title under 32 characters.
3. Run the build; fix every error; read the warnings.
4. Add the process to the "What's inside" table of the README.
5. Open a pull request with the CSV, the regenerated docs and workbook, and a sentence on why the process is needed.
